# Foundations open issues

- Targeted edits of a mounted background editor view still return `unsupported-view`; a view-aware adapter must preserve selection and history before allowing them.
- The public `editorViews` API addresses mounted views and validates view generation, editor pane, and content version. It exposes the primary selection in explicit editor coordinates; these positions cannot be used as Markdown source edit offsets. The current layout has one editor view; two live split panes from draft #90 are not integrated.
- Legacy `context.editor.updateMarkdown` now rejects a stale pending command target. Background callbacks outside a command remain active-only; use `context.documents` for captured asynchronous edits.
- Workspace closed-file update requires explicit metadata reset. Rename/trash/source unlink and folder moves still have same-user path-swap races without native identity-bound, no-replace filesystem operations. A failed folder move may leave its reserved empty destination. Paged listing bounds IPC payloads but may walk the retained tree from its start for each page.
- Workspace watcher events identify generation and ordered invalidations, but cannot truthfully report every external mutation's origin or content version.
- Graph, Tags, and Backlinks use the shared metadata query service. Source extraction still includes wiki links and hashtags regardless of renderer flavor. Text search is a bounded scan, not an indexed/ranked search; worker offload remains open.
- Rich completion rejects wiki-link source syntax without a certified mapping. Writing suggestions and the proof addon offer wiki links in source mode and tags in both modes. Context actions can consume right-click while async providers return no actions; this editor has no native fallback menu yet.
- Installed addons share the renderer and global preload bridge. Main-owned activation checks prevent cooperative stale requests; they do not isolate hostile addon code or prevent another addon from spoofing an ID.
- Host network, credential storage, and selected import/export are narrow first slices. Credentials cannot yet be applied to a granted network request, and existing export targets are rejected rather than replaced. Linux secret-store, Windows file, and Wayland shortcut behavior need platform runs. Same-realm addons can spoof another ID, so prompts do not provide adversarial per-addon isolation.
- Static site export now whitelists published data and sanitizes renderer HTML before serialization. Its URL-encoded Mermaid SVG image path still needs a site-runtime fidelity check; no broad guarantee is made for arbitrary installed addon renderers.
- Command menus still need verified explorer/editor slots and toolbar dispatch through the shared command registry. Existing optional global-shortcut callback form loses captured command context; its command-ID form preserves it.
- Downstream quick-note addon in PR #84 uses a global shortcut callback, which loses `global-shortcut` command context; its dialog also resolves the current workspace at save time, so a focus/workspace switch can retarget a write. This is a compatibility finding, not a change to that PR.
- #90 remains a draft at `909ec080` stacked on #99 at `2ebb38fa`. Its two editable panes are absent from this integration branch; a read-only three-way comparison found 12 conflicts across eight files. Direct replay could discard current save-token guards. A composed port needs per-pane view IDs and split/focus/save/completion tests; no composed build was run.
- Full integration check at `e48290d` had 15 desktop failures and one cancellation. Later focused integration groups passed, including the previously failing addon shortcut test. A full final-head run is needed before calling the branch ready.
- Baseline and candidate performance evidence, including startup, input, targeted edits, indexing, activation, completion, and retained memory, remains to be measured on a quiet reference machine.
