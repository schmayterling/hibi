# Foundations open issues

- Targeted edits of a mounted background editor view still return `unsupported-view`; a view-aware adapter must preserve selection and history before allowing them.
- The public `editorViews` API addresses mounted views and validates view generation, editor pane, and content version. It exposes the primary selection in explicit editor coordinates; these positions cannot be used as Markdown source edit offsets. The current layout has one editor view; two live split panes from draft #90 are not integrated.
- Legacy `context.editor.updateMarkdown` now rejects a stale pending command target. Background callbacks outside a command remain active-only; use `context.documents` for captured asynchronous edits.
- Workspace closed-file update requires explicit metadata reset. Rename/trash/source unlink and folder moves still have same-user path-swap races without native identity-bound, no-replace filesystem operations. A failed folder move may leave its reserved empty destination. Paged listing bounds IPC payloads but may walk the retained tree from its start for each page.
- Workspace watcher events identify generation and ordered invalidations, but cannot truthfully report every external mutation's origin or content version.
- Graph, Tags, and Backlinks use the shared metadata query service. Source extraction still includes wiki links and hashtags regardless of renderer flavor. Text search is a bounded scan, not an indexed/ranked search; worker offload remains open.
- Rich completion accepts exact wiki-link syntax in safely mapped plain paragraphs; marked or otherwise unproved rich ranges still require source mode. Writing suggestions and the proof addon offer links and tags in both supported editors. Context actions can consume right-click while async providers return no actions; this editor has no native fallback menu yet.
- Installed addons share the renderer and global preload bridge. Main-owned activation checks prevent cooperative stale requests; they do not isolate hostile addon code or prevent another addon from spoofing an ID.
- Host network, credential storage, and selected import/export are narrow first slices. Stored bearer credentials can accompany an approved HTTPS GET; authenticated redirects fail closed. Existing export targets are rejected rather than replaced. Linux secret-store and Wayland shortcut behavior need platform runs. Same-realm addons can spoof another ID, so prompts do not provide adversarial per-addon isolation.
- Static site export now whitelists published data and sanitizes renderer HTML before serialization. Its URL-encoded Mermaid SVG image path still needs a site-runtime fidelity check; no broad guarantee is made for arbitrary installed addon renderers.
- Explorer/editor context slots and toolbar command-ID dispatch now use the shared registry. The optional global-shortcut callback form still loses captured command context; its command-ID form preserves it.
- The quick-note addon from draft PR #84 is composed on this integration branch without changing its PR branch. Its command-ID shortcut captures the chosen workspace before opening the dialog, and the chosen inactive workspace remains available beyond the five recent entries. Native path validation still has a same-user check/use race before the exclusive write.
- #90 remains a draft at `909ec080` stacked on #99 at `2ebb38fa`. A separate `may/foundations-split-compat` branch replays its three commits but has not passed a composed build. Its two editable panes are absent from this integration branch; retained-session activation and failed-focus recovery still need review and tests before use.
- Full local `npm run check` at `600e4a7` passed 879 tests with none failed and two skipped. The `fb0a56a` hosted matrix passed both ubuntu jobs and all three `1/2` jobs; mac `0/2` failed a frontmatter source handoff assertion, and windows `0/2` failed three filesystem-semantic assertions. Focused test fixes are integrated; a fresh clean matrix is running. The final integration head still needs an exact-head full gate.
- Paired startup and text-insertion evidence is in `BENCHMARKS.md`. The 15,499-character rich benchmark fixture rejected its first edit on baseline and candidate, so document-open timing is unmeasured. Targeted edits, command dispatch, completion latency, per-operation IPC costs, packaged startup, disabled-addon evaluation, and retained memory still need measurements.
