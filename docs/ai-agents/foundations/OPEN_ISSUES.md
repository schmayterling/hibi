# Foundations open issues

- Mounted background rich and source views now accept targeted edits with generation, version, and mapping checks. Unmounted or unprovable rich ranges still return an explicit unsupported result; they cannot be silently rewritten through a different view. Two editable split panes are integrated, but final-head full and cross-platform validation remains open.
- The public `editorViews` API validates view generation, pane, and content version. Its primary selection uses editor coordinates, which are not interchangeable with Markdown source edit offsets. Legacy `context.editor.updateMarkdown` rejects a stale pending command target; callbacks outside a command remain active-only and should use `context.documents` for captured asynchronous edits.
- Workspace closed-file update requires explicit metadata reset. Rename/trash/source unlink and folder moves still have same-user path-swap races without native identity-bound, no-replace filesystem operations. A failed folder move may leave its reserved empty destination. Paged listing bounds IPC payloads but may walk the retained tree from its start for each page.
- Workspace watcher events identify generation and ordered invalidations, but cannot truthfully report every external mutation's origin or content version.
- Graph, Tags, and Backlinks use the shared metadata query service, and source extraction now follows the active built-in syntax. Text search remains a bounded scan rather than an indexed or ranked search; worker offload and final-head end-to-end query measurements remain open.
- Rich completion accepts exact wiki-link syntax in safely mapped plain paragraphs; marked or otherwise unproved rich ranges still require source mode. Writing suggestions and the proof addon offer links and tags in both supported editors. Context actions can consume right-click while async providers return no actions; this editor has no native fallback menu yet.
- Installed addons share the renderer and global preload bridge. Main-owned activation checks prevent cooperative stale requests; they do not isolate hostile addon code or prevent another addon from spoofing an ID.
- Host network, credential storage, and selected import/export are narrow first slices. Stored bearer credentials can accompany an approved HTTPS GET; authenticated redirects fail closed. Existing export targets are rejected rather than replaced. Linux secret-store and Wayland shortcut behavior need platform runs. Same-realm addons can spoof another ID, so prompts do not provide adversarial per-addon isolation.
- Static site export now whitelists published data and sanitizes renderer HTML before serialization. Its URL-encoded Mermaid SVG image path still needs a site-runtime fidelity check; no broad guarantee is made for arbitrary installed addon renderers.
- Explorer/editor context slots and toolbar command-ID dispatch now use the shared registry. The optional global-shortcut callback form still loses captured command context; its command-ID form preserves it.
- The quick-note addon from draft PR #84 is composed on this integration branch without changing its PR branch. Its command-ID shortcut captures the chosen workspace before opening the dialog, and the chosen inactive workspace remains available beyond the five recent entries. Native path validation still has a same-user check/use race before the exclusive write.
- The #90 split-pane composition is integrated without updating its draft pull request. Its two live editors have focused coverage for focus, save, target edits, and flavor retention; the exact-head full suite and hosted matrix must still pass before claiming complete compatibility.
- The latest completed local full check at `1e05ad1` passed 907 tests, failed one Graph empty-state assertion under suite load, and skipped two. The assertion passed in isolation. The later focused integration set passed 28/28 at `86571c8`. Final-head `npm run check` remains pending; do not report the integration gate green from a focused rerun.
- A Windows hosted job at `86571c8` failed because the packed SDK test passed an absolute drive-letter archive path to `tar`. The test now passes a relative archive path, but the fix still needs an exact-head hosted Windows result. Linux secret-store and Wayland shortcut behavior remain unverified.
- Paired startup and input measurements in `BENCHMARKS.md` cover an earlier candidate, not final integration. The 15,499-character rich fixture rejected its first edit on both baseline and candidate, leaving document-open and large-note input unmeasured. Targeted edits, command dispatch, completion latency, per-operation IPC bytes/calls, packaged startup, disabled-addon evaluation, and retained owner memory still need evidence. The two-pane trace harness observes synthetic keypress-to-changed-screenshot receipt, not physical input or display scanout.
